How one failed payment travels through the system

Every box is a real file. Follow the arrows top to bottom — this is the order the code runs.

1

Razorpay A payment fails

A real failed payment fires a webhook  ·  or the benchmark replays one from data/cases.jsonl (300 cases, fixed seed)

POST /webhook/razorpay
2

Backend Verify & open a case

SignatureVerifier.java checks HMAC over the raw bytes → bad = 401. Good → RazorpayWebhookController.java creates a case and calls the agent

AgentClient.java → HTTP → agent /decide
🧠 Agent — decides, can't actSeparate Python process. No database, no gateway, no money. Only reasons and asks.
🛠️ Backend — acts, enforces rulesOwns the gateway, the database, the audit log. The only thing that can touch money.
3

Agent · LangGraph The decision loop

Wired in graph/build.py, nodes in graph/nodes.py

diagnose  →  decide  →  guard  →  execute  →  check_outcome
↳ diagnose — error reason → cause  (dictionary in graph/ev.py, not an LLM)
↳ decide — rank by expected value: P(recovery)×amount − cost  (llm.py picks; falls back to pure EV if the model is down)
↳ check_outcome — failed? loop back to decide with that action struck off
4

Policy gate guard — nothing skips this

graph/guardrails.py reads agent/policy.yaml: attempt caps, contact caps, quiet hours, opt-out, the ₹25,000 approval line. Veto → back to decide. Over ₹25k → human.

amount > ₹25,000
5

Human-in-loop Pause for approval

Graph interrupts, checkpointed into Postgres — survives a restart. Escalations.jsx is the queue; approve → the graph resumes exactly where it stopped.

6

Gateway execute — act on the winning action

SimulatedGateway.java (benchmark, deterministic)  ·or·  LiveRazorpayGateway.java (real test API → a real rzp.io link, returns PENDING). Same graph — GATEWAY_MODE picks.

7

Every step logged + learns

DecisionLogger.java writes every decision to decision_log — the agent can't act without logging. Each outcome updates a Beta posterior in ev_stats, so probabilities learn.

payment_link.paid webhook → case RECOVERED
8

Dashboard The whole story, visible

Dashboard.jsx · CaseDetail.jsx render the real decision_log — the timeline judges see IS the audit trail. 3.3× naive recovery, half the attempts.
